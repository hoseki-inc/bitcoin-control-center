# Security policy

## Reporting a vulnerability

Don't open a public issue for a suspected vulnerability. Use the repository's **Security → Report a vulnerability** flow to create a private GitHub security advisory.

Include the affected version, reproduction steps, impact, and any suggested fix. Don't include real wallet descriptors, exchange credentials, seed material, or other personal data.

## Supported versions

Fixes go to `main` and the latest release. Upgrade before reporting an issue that a newer release has already fixed.
